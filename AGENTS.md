# Today — работа с проектом

## Контекст и границы

- Это нативное меню-бар приложение macOS (Swift/SwiftUI/AppKit, macOS 13+,
  Intel и Apple Silicon) и Windows-приложение в трее (C#/WPF/.NET 10, x64/ARM64).
  Не превращать их в сайт и не добавлять сервер без запроса.
- Перед изменениями проверить рабочую копию, HEAD и git status. Сохранить чужие
  изменения. Развивать существующие App / Domain / Data / Presentation небольшими пакетами.
- Если данных недостаточно, прямо сказать «Я не знаю». Отделять факты, предположения
  и непроверенные риски. Не заявлять о проверке, которую не выполняли.
- Не читать и не менять личные задачи ради тестов. Использовать временные хранилища
  и синтетические данные. Совместимость существующих tasks.json и categories.json обязательна.
- Установка навыков не разрешает публикацию: commit/push, релиз и внешние сообщения —
  только по запросу. Не менять глобальные настройки Codex, автозапуск и разрешения macOS.
- Не менять синхронизированные файлы родительского проекта и `sources/`.

## Проектные навыки

Перед применением читать полный SKILL.md и кратко сообщать пользователю, зачем он нужен.
Для перечисленных навыков использовать проектную копию, не смешивая её с одноимённой
глобальной. Источник переноса и контрольные суммы — `.agents/skills/sources.json`.

| Навык | Когда применять |
| --- | --- |
| [ponytail](.agents/skills/ponytail/SKILL.md) | При изменении и проверке кода: проследить поток данных, переиспользовать существующее, предпочитать стандартные возможности Swift/AppKit новым зависимостям |
| [frontend-design](.agents/skills/frontend-design/SKILL.md) | При изменении интерфейса: композиция, отступы, типографика и понятность действий |
| [grill-me](.agents/skills/grill-me/SKILL.md) → [grilling](.agents/skills/grilling/SKILL.md) | Только по запросу на разбор открытого продуктового или архитектурного решения; это один навык с зависимостью, не два ревьюера |

- Ponytail не отменяет согласованные функции, читаемость, безопасность, доступность,
  обработку ошибок и регрессионные тесты. Использовать существующий Swift Testing,
  не заменять его одиночными assert и не удалять тесты ради минимальности.
- Сохранять текущий минималистичный стиль: TodayPalette, системные шрифты macOS,
  реальные скругления, светлую и тёмную темы, полный текст задач. Приоритеты монохромные.
  На Windows — та же палитра и компоновка, системный Segoe UI; реализация в `Windows/`.
  Для точечной UI-правки не выбирать заново стиль, палитру и шрифты. Веб-примеры навыка
  не означают переход на CSS/HTML, мобильный сайт или замену утверждённого календаря.
- При недоступном Skill tool для grill-me прочитать проектный grilling напрямую.
  Не начинать интервью только из-за установки навыка и не пересогласовывать принятые решения.

## Агентные роли

| Роль | Задача |
| --- | --- |
| [code_explorer](.codex/agents/code_explorer.toml) | Найти точки изменения, зависимости и существующие тесты, без записи |
| [developer](.codex/agents/developer.toml) | Реализовать ограниченный пакет в назначенных файлах |
| [ui_qa_reviewer](.codex/agents/ui_qa_reviewer.toml) | Проверить затронутый нативный интерфейс, клавиатуру, фокус и обе темы |
| [data_safety_reviewer](.codex/agents/data_safety_reviewer.toml) | Проверить сохранение, совместимость JSON, даты, напоминания и жизненный цикл задач |

- Роли — средства для делегирования, не постоянно работающие процессы. Подключать
  по разрешению пользователя на делегирование или независимую проверку; сама установка
  не является поручением запускать всех. Для простой правки отдельный исполнитель не нужен.
- Передать абсолютную рабочую копию, HEAD/базу, точный diff или файлы, ожидаемый
  результат, ограничения и уже выполненные проверки. Один изменяемый файл — один владелец.
- Только основной агент координирует работу. Субагенты не делегируют дальше,
  не создают отдельные пользовательские чаты и не запускают общий цикл ревью повторно.
- Проверяющие не меняют файлы или пользовательские данные. Текстовый запрет записи
  не является отдельной песочницей: фактические разрешения наследуются от родителя.
- Если инструмент не поддерживает выбор именованной роли, основной агент читает её TOML
  и передаёт полный developer_instructions обычному субагенту с узким заданием.
  Название задачи само по себе роль не подключает. Модель и effort не переопределять.
- Проверить замечания по коду или воспроизведению, исправить подтверждённое и повторить
  затронутые проверки. Не дублировать агентами уже успешный общий тестовый прогон.
- Итог ревью: подтверждённые дефекты с file:line/сценарием/последствием, отдельно риски
  и неприменимые области. Не называть чтение кода визуальным или независимым тестированием.

## Проверки и передача

- Windows: `dotnet run --project Windows/Today.Core.Tests`, затем
  `dotnet build Windows/Today.Windows`. На Windows дополнительно запустить собранный
  `Today.exe --smoke-test <папка снимков>`. Этот режим использует временные данные и
  не трогает автозапуск или уведомления. Для упаковки — `scripts/build-windows.ps1`.
  Сборка на Mac не доказывает запуск на Windows; CI-проверка x64 не доказывает запуск ARM64.
  Не менять реестр автозапуска, системный трей и личные задачи ради тестов.

- Код: `./scripts/test.sh`. Изменения интерфейса дополнительно проверять на синтетических
  снимках: `TODAYBAR_SNAPSHOT_DIR="$PWD/.build/ui-previews" ./scripts/test.sh`.
- UI: обе темы, длинный текст и переносы, пустой поиск, история, раскрывающиеся меню,
  Enter/Shift+Enter, копирование/вставка, фокус между поиском, задачей и полем ввода.
  Снимок не доказывает кликабельность меню; указывать, что действительно проверено.
- Сборка: `./scripts/build-app.sh`; затем проверить подпись и обе архитектуры.
  Не утверждать запуск на Intel/старой macOS по одному факту успешной сборки.
- Не пересобирать приложение для правок только инструкций. Обновлять README при изменении
  пользовательского сценария. Финал по-русски: результат, проверки и ограничения.
